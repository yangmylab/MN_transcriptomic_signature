# BAP audit — Paper 1 (MN multi-cohort transcriptomics)

**Protocol:** `bioanalyst` v1.1.0 (governed bioinformatics analysis protocol)
**Audit date:** 2026-11-18
**Scope:** all 48 R scripts, 221 result tables, 181 figure PDFs (+ rasters), the manuscript and the
reproducibility package, as they exist in `/run/media/meng/MY_Data/MN/Paper_1`.
**Mode:** §11 script-revision mode — the project predates the BAP layout, so the protocol is applied
as an audit against the existing tree rather than by scaffolding a parallel directory.

---

## 1. Verdict

> **Reliable with important limitations.** The primary computational claim (a compartment-resolved
> glomerular signature and a four-gene classifier with external discrimination) is supported at
> **E2** by an independent array cohort (ERCB), an independent RNA-seq cohort, a laser-capture cohort
> and an alternative-CDF reprocessing. No Critical defect was found. One **Major metadata defect**
> was found and fixed during this audit (BAP-01). The remaining limits are stated, not hidden: the
> classifier is a discrimination instrument that needs per-platform recalibration and has no
> protein-level validation yet (E4 pending), and no clinical outcome is available.

**Strongest thing this study shows:** a four-gene glomerular panel reproduces external discrimination
across four independent sample sources and collapses to chance in the tubulointerstitium of the same
patients — a specificity result that is hard to obtain by accident.

**Most likely reason a reviewer would reject it:** only 21 MN cases in the external array cohort, so
the strict refit-based permutation null does not reach significance (*p* = 0.11) — the manuscript
already says so.

## 2. Method, and why the checker was calibrated first

The first pass of the audit script produced two `FAIL`s (`gsm` not unique; QC policy missing). Both
were **the checker's assumptions**, not project defects: the key column is `gsm` (1,623 real GEO
accessions + placeholders) and the QC policy table is `qc_outlier_policy.csv`, not
`03d_qc_policy.csv`. Per BAP §11.2 (*"a checker you have not calibrated is a random number
generator"*), every check was re-run against the real column and file names before any verdict was
recorded. The corrected run is what this report is based on.

## 4. Findings register

### Major

**BAP-01 — mixed-provenance sample key; 134 local-index collisions. FIXED.**
`output/tables/sample_metadata.csv` uses one `gsm` column as both the GEO accession and the matrix
column key. Only the array series carry a real accession: **1,623 `GSM####`**, **473 `Sample_N`
local indices** (GSE197307 282, GSE182380 199), **69 submitter ids** (GSE216841, GSE73953). Because
the two RNA-seq series both number their samples 1..n, **134 labels collide** — which is exactly the
P-2 identifier-collision trap the project documents elsewhere.
*Not a science error:* the analysis already refuses participant linkage for the RNA-seq cohorts
(`MN_overlapping_discovery = NA`, role "independent RNA-seq cohort"), and no analysis set contains a
duplicated sample. The risk was that a reader or a future join would treat `Sample_1` as a GEO
sample shared by two cohorts.
*Fix:* `R/01a_build_sample_metadata.R` now writes `id_type` (`geo_gsm` / `local_index` /
`submitter_id`) and `id_is_globally_unique`. The change is **purely additive** — all pre-existing
columns verified byte-identical (`identical()` TRUE, 2,165 rows). Three assertions added to
`99_verify_phase_a.R` (→ 54 assertions), all passing.

### Minor

**BAP-02 — stray deliverable artefacts. FIXED.** `output/figures/` contained three orphan rasters
(`Fig2_discovery_and_meta-2.jpg`, `Fig5_biomarker_panel-2.jpg`, `Fig6_atlas_and_deconvolution-2.jpg`)
and `tools/__pycache__/`. Removed; 177 PDF / 177 raster now pair exactly.

**BAP-03 — unseeded stochastic step.** `R/07b_scrna_qc.R` calls `scDblFinder()` without `set.seed()`,
so doublet assignment is not byte-reproducible (it does not affect current results — the atlas is
frozen and the object is saved — but a re-run could shift a handful of cells). Recommend one
`set.seed(20261019)` in the script header. **Not applied**: re-running 07b (≈25 min) is out of scope
for an audit and must be an explicit request.

**BAP-04 — parallelism coverage below the standing rule.** 9 of 47 scripts parallelise. Most are
genuinely serial (metadata, normalisation writes, deterministic transforms, verifiers). Two heavy
ones are serial without a written waiver: `07b` (49 samples, ≈25 min) and `08f` (module ORA,
≈12 min). Per BAP R4 every non-complying script needs either a fix or a
`# Parallelism: not needed — <reason>` waiver; recommend adding the waiver comment rather than
rewriting a settled pipeline.

**BAP-05 — stale hard-coded label (already fixed today).** `09d_leave_one_out.csv` labelled its first
row "all 5 genes" while `n_genes = 4`; `R/09d_panel_mechanism.R` now derives the label from
`length(panel)`.

### Observations (no action)

- **Validation independence holds.** Discovery array, ERCB array, two RNA-seq cohorts and the LCM
  cohort are four separate sample sources; the model was frozen before validation and the
  standardisation statistics come from discovery only (after the F62 harmonisation fix).
- **No claim-verb violations.** A scan for `drives / regulates / proves / mechanism / causes /
  demonstrates` in the manuscript returned 4 hits: two are background epidemiology ("commonest
  *cause* of nephrotic syndrome"), one is "the reimplementation was *validated* against the
  submitters' matrix" (a technical check, correctly described), one is inside a reference title.
  Enrichment is never called activation; the panel is never called validated at protein level.
- **Negative results are carried at equal prominence** (subtyping non-reproducibility, TI null,
  refit-null *p* = 0.11, FSGS weakness) — as the protocol requires.
- **Provenance is complete**: 13 GEO accessions, per-cohort release decisions, seeds, versions in
  `environment/renv.lock`, path-independent drivers.

## 9. What this audit did **not** do

- Did **not** re-run the analysis pipeline (that would be an E2E run requiring an explicit request).
- Did **not** change any statistic: the only code changes are additive metadata columns plus three
  assertions, and the pre-existing metadata values were verified byte-identical.
- Did **not** download new data. No dataset is missing for any claim the paper makes; the two
  genuine gaps (clinical variables B2, participant map B7) are **access-controlled**, not
  unavailable — they require a data-use request, which `Manuscript/DATA_REQUESTS.md` already
  specifies.
